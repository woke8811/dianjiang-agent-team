# WorkBuddy 原生落地指南（本版原创核心）

这份文件把抽象的 MAS 规则翻译成 WorkBuddy 上"具体敲什么、调什么"，是原版 MAS 与 ruflo 都没有的部分。

## 1. 能力对照与调用

| MAS 概念 | 原生手段 | 具体动作 |
|---|---|---|
| 真实独立执行上下文 | `Agent` 工具 | 生产、审核各起一次子代理调用，各给独立任务提示词；审核子代理不得复用生产子代理的会话 |
| 首席统筹 | 主会话自身 | 主会话保留"定目标/派活/核收/交回"，不把成品正文交给自己写 |
| 任务台账 | `TaskCreate` / `TaskUpdate` / `TaskList` | 派活即建任务（待收）；状态变化立即 TaskUpdate；只转阶段不删记录 |
| 持久台账文件 | 工作区 `.mas-ledger.md`（可选） | 需要跨会话审计时，把登记行追加到工作区文件，只追加不改写 |
| 共享记忆 | `.workbuddy/memory/YYYY-MM-DD.md` 与 `MEMORY.md` | 把"已核结论+版本+出处"写入项目记忆，下次复用、避免重复调查 |
| 并行分工 | `Agent` 的多次并发调用 | 互不依赖的执行席（如情报+学习）可在同一条消息里并行启动 |
| 后台长任务 | `Agent` 的 `run_in_background` | 需要较长耗时的子任务置后台，用 `TaskOutput` 取结果 |

## 2. 一次完整三席协作的跑法（标准范例）

前提：任务可分工且需互检（例："为一份产品方案做竞品调研并产出结论页"）。

**第 0 步｜主控判定**
先问"这次分工收益 > 协调开销吗？"。若只是查一个价格、改一行字——单干，结束。确认可分工后继续。

**第 1 步｜复述与登记**
在主会话复述：目标、收件位置、验收标准、将启用哪些执行上下文。用 TaskCreate 建任务 M-01，状态=待收，登记行写入台账。

**第 2 步｜派生产席**
用 `Agent` 起一个子代理（命名如 `producer`），传入 `templates.md` 第 3 节的角色调用模板：
- 目标与锁定项、输入版本、应交物、收件位置、验收条件、授权出处。
- 明确"缺事实报缺，不编造；只做受影响部分"。
子代理把成品写到约定收件路径，回件写版本与证据。收到后 TaskUpdate → 已接单/已收到成果（待核）。

**第 3 步｜独立审核（关键）**
**另起一个全新的 `Agent` 子代理**（命名如 `reviewer`），绝不与 producer 共用会话：
- 只给它成品路径 + 验收条件 + 原始指令，不给 producer 的自述结论（避免污染盲审）。
- 要求按审核官卡核事实/标准/质量，只回"通过 / 退回修改 / 提交首席"三选一，并给原因+位置+所核版本。
- 若审核席看过既有结论，须如实声明"非盲审"。

**第 4 步｜判与交**
- 通过：主控亲自打开成品核对（证据先行五步），确认无误 → TaskUpdate 已验收（待有权者接受）→ 在原会话把可打开的成品交回，请用户验收。用户点头后才算真正关闭。
- 退回：TaskUpdate 退回 → 把"退回修改"连同具体位置交回**原** producer 子代理（可 resume 同一 agent），只改受影响处，出新版 → 回到第 3 步用新审核上下文再核。

**第 5 步｜收尾与沉淀**
写收尾三模板；把对本任务有用的已核结论+版本+出处写入 `.workbuddy/memory`，供后续会话复用（这是 ruflo"共享记忆减少重复调查"的原生实现）。

## 3. 常见误用与纠正

| 误用 | 纠正 |
|---|---|
| 用同一会话"现在你是审核官"来互检 | 不算独立审核；必须另起真实子代理 |
| 把 producer 的自述结论一起喂给 reviewer | 污染盲审；只给成品和验收条件 |
| 简单任务也起三席 | 开销>收益；单干 |
| 审核"通过"就直接告诉用户"做完了" | 还要主控亲核 + 有权者接受，缺一不可 |
| 审核席发现问题就自己动手改 | 审核只审不改；退回原生产席 |
| 把"已签收"当成后续节点已关闭 | 逐节点按状态机判定，未完保持未完 |
| 声称"多智能体帮我省了 token" | 不实；收益在质量与互检 |

## 4. 与 ruflo 的取舍说明（为什么不直接装 ruflo）

- ruflo 的 swarm/memory/hooks 依赖 MCP server 与 npm 包，WorkBuddy 默认不提供 `mcp__claude-flow__*` 工具；直接装 ruflo 会出现"skill 加载了但工具用不了"。
- 本版用原生 `Agent` + 任务系统 + memory 实现同等能力，零外部依赖、即装即用。
- ruflo 的"成本追踪/最小起步/改进需对基线实测"等理念已吸收进本 skill 的成本纪律与哲学章节；其宣传的 benchmark 数字未经本环境验证，不在本 skill 中引用为事实。
