# cost-mode · 省 token 优先纪律（细则）

## 0. 定位（先读这条）

本 skill 的 token 节省来自**不花 / 少亏 / 不重做**，不来自"这次任务本身花得更少"：

- 多智能体全局总耗结构性高于单干（派单重复上下文 + 审核重读成品 + 协调消息）。
- 省的三处：① 默认单干（多数任务省掉 100% 队伍开销）② 断路器 ≤2 次退修（死循环是 token 第一杀手）③ 开工查重 + 共享记忆复用（不重做已核结论）。
- 起队花的那份钱是**保险费**（防 solo 返工循环烧 10 倍），不是成本优化。
- 与宿主省 token 工具的关系：save-token（压输出）、magic-context（回收上下文 + 保缓存）、ctx_memory（复用已核结论）与本纪律**叠加**，不互相替代；报告中声称节省时写清属于哪一层。
- 禁止在任何报告中写"本 skill 省了 N% token"——没有这种实测口径；可写的只有"默认单干省掉全部队伍开销；起队任务的节省来自断路器 / 查重 / 回件压缩，不来自队伍本身"。

## 1. 成本门禁（派单前判定，三条全中才准起队）

| # | 判据 | 可验证写法 |
|---|---|---|
| 1 | 可拆分 + 需互检 | 任务能产出 ≥2 个可独立核验的子件 |
| 2 | `e × R > C` | e = solo 出错概率；R = 返工代价（≥1 倍全套队开销，死循环时 ∞）；C = 全套队协调开销 |
| 3 | 出错代价高 | 对外 / 生产 / 涉凭据资金 / 需留痕 |

**实测常数**（DSH 环境，2026-11 三席试验，Agnes 渠道，91 请求 2.67M token）：

- 全套队（三席 + 1 轮退修）≈ **3~4 ×** 单趟 solo
- 审核席占全套 ≈ **40%**（质量税）
- 无声失败后重派 ≈ **2.5 ×** 单席（含死掉那席的半程浪费）
- 主会话每席净入流（派单 + 回件）≈ **2~5K**，中间工作全部隔离在子席

估不出 e / R 时取默认 e=30%、R=2C：非琐碎任务几乎都过闸；琐碎任务不用算，直接单干。

## 2. 回件压缩（主会话节省的硬上限）

- 回件 **≤500 字**，结构固定：`结论（通过/退回/提交首席）→ ① 位置（文件+行 / 工具+字段）② 可验证判据 ③ 证据指针（定位器/命令）`。不写散文，不贴成品全文。
- 过程（中间输出、试错路径）留在子席上下文，**不回传**——主会话的节省 = 报告里没有的东西。
- 成品写到指定位置（`deliverables/<任务>/v<N>`），回件只给位置 + 版本号；审核席与首席各自打开同版核验。
- 回件压不进 500 字本身是红旗（说明未收敛），首席叫停，定"退修 or 熔断"，不带病进下一轮。

## 3. 缓存前缀（全价输入 → 缓存价）

- 提示词头部固定块 = 角色卡 + 铁律 + 模板 + 本细则要点，**跨派单字节稳定**（不改写、不换序、任务内容不混进去）。
- 任务特定内容（目标 / 锁定项 / 本版 diff）追加在头部之后。
- 原岗退修走 `send_message` 续原席（上下文自然接续，缓存全命中）；只有原席死亡才重派，重派提示词复用同一头部块。

## 4. 串行默认

子代理**逐个派、等回执再派下一个**。仅当三条全中才允许并行（≤2 席）：① 各席产出完全独立 ② 渠道近 1 小时无无声失败 ③ 并行不共享同一份待核成品（避免双席重复读同一版本）。
实测依据：不稳渠道上高频 burst → 无声失败 → 重派，浪费 ≈ 2.5 倍单席；串行时失败立即重派，无并行席陪跑。

## 5. 验证方法（真省了没有）

每次起队后从宿主会话日志（`usage` 字段）汇总三组数：
1. 子席总耗（Σ input + output，缓存读单列）
2. 主会话净入流（派单 + 回件 + 首席核验读数）
3. solo 基线（同类任务单趟成本，可取历史 solo 会话或估 0.3~0.5 × 全套队）

判读：省 = ① 主会话没被中间工作撑大（对照 solo 基线的主会话增长）；亏 = 子席总耗 − solo 基线（这是保险费，如实写进交回报告）。某次全局总耗 > 4 × solo 基线 → 回查门禁 e/R 估算，把偏差记进共享记忆。

## 6. 边界（不越线声称）

本纪律不改变"MAS 更费"的事实，只保证**该花才花、花了不白**。涉及渠道不稳（如免费档限流）时，把"重派成本"计入 C 再判门禁；反复失败 3 席 → 冻结循环，/拍板 交本人定线路。
