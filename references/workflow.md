# 主工作流、状态机与护栏细则

## 1. LOOP 六字诀

`派 → 接 → 做 → 核 → 判 → 交`，每一步有记录、有证据、有明确责任人。出问题只退回受影响的那一环（原岗退修），不推翻重来，也不让已验证的部分白费（证据接续）。

三权分立式护栏（互相独立，任一席不能替代其他席，也不新增审批关口）：
- 一席核成品（审核官：核事实、标准、质量）
- 一席查决定是否落实（督查官：对照台账核登记/承接/对应）
- 团队外的复核者检查协作方式（必要时由首席点对点联系）

## 2. 主工作流（一条线走到底）

```
用户定目标
  ↓
首席确定实际执行席（按任务选，不是永远交生产席）
  ↓
执行席制件（只做受影响部分，缺事实/报价就报缺，不编造）
  ↓
独立审核（另一个真实上下文打开同版成品）
  ├─ 通过 ──→ 首席核收 → 原会话交回 → 有权者验收
  ├─ 退回修改 ──→ 交回本单原执行席，只改受影响处 → 出新版本 → 回到"独立审核"
  └─ 提交首席 ──→ 由首席升级处理
```

## 3. 任务状态机（严格执行）

任务阶段只有 6 种，**只有"已验收"或授权"已取消"能让任务退出未完清单**。待收、已接单、已收到成果（含"核验通过待决定"）、退回，全部算未完。

| 阶段 | 含义 | 进入条件 |
|---|---|---|
| 待收 | 已派活、尚未接单 | 派活即登记，写明谁干/谁收/到点谁查/结果放哪/做到什么算完 |
| 已接单 | 执行席确认承接 | 收到明确"已接单"回执或开工证据；"消息收到了"不算接住 |
| 已收到成果 | 成果已交、待核或核验通过待决定 | 成果入口可访问 |
| 退回 | 需原岗改受影响处 | 审核席给"退回修改"结论 |
| 已验收 | 核验通过且有权者接受 | 有接受决定或可回查授权 |
| 已取消 | 授权取消 | 本人明确授权 |

记录只追加、不改写，保留原期限/旧回件/失败历史。

## 4. 过程事件（不改变阶段）

- **叫开工**：授权/放行一出，派活人当场叫下一棒开工；收到"已接单"或开工证据才算接住。
- **续期**：执行人报新时间只是"新预计"，不是正式改期；原承诺保留，标"正式改期：未确认"，经有权人确认后才算新承诺。确认前仍按原承诺算逾期。
- **升级**：追不上执行人、做不到时追加，照实写拖了多久。
- **点名**：把自己派出去的未完活全看一遍，逐件判断，最后写"点名完，剩 N 件，最早几点到"。
- **不自建定时任务**：到点靠登记 + 醒来先查；不为"快好了"建闹钟/后台循环，除非本人亲口要求且写明到期自删。

到点查的是所有未完项，不是只查"过点没人接"的。按任务标识找最近一条有效阶段记录，再按对应节点处理。

## 5. 三权分立各席边界

### 审核官：只审不干活
核事实（数字、日期、出处真实、可复算、没编造）、标准（符合已批准条件、隐私脱敏、危险动作需本人确认）、质量（成品可打开、用途职责完整）。每次只给三种结论之一：**通过 / 退回修改 / 提交首席执行官**，并写清原因、要改的具体位置、所核版本。不改别人文件、不替人重写、不派活、不审自己做的东西、不代替用户做最终取舍。法律风险不在结论里直接裁断，只查"有没有漏给法商官看"。

### 督查官：事后第二道，不加关口（只核流程，不碰成果）
对照原始指令、有效决定和台账，核重要事项是否登记、有人承接；核**记录/回执/批准是否对应**；查规则冲突和执行偏差。

**审核去重铁律**：成果的结论权归审核官**独有**——核事实、标准、质量并给"通过/退回/提交首席"三选一的是审核官。督查官**不对成果下任何结论、不重复核成品**，只核流程记录本身是否齐全、可追溯。这样断掉"两个席重复核同一份成果、结论互相打架"的重复审核。

不拍板、不验收、不放行、不派工、不改期；不改台账/规则/技能/审核结论/成果；不自建定时巡检。重要承诺或授权出现实质争议、或重要偏差经正常渠道未处理时，可直报用户并同步首席——这是唯一的越级通道。

### "提交首席"分支的标准处置（原名空白，此处补齐）
审核官给出"提交首席"而非"通过/退回"时，首席必须按以下顺序处理，不得搁置或自行拍板放宽标准：
1. 读审核官写明的升级原因与所核版本；
2. 判断属于哪一类：①超授权/危险动作 ②目标或锁定项本身有歧义 ③成品缺关键输入 ④审核席与执行席结论冲突；
3. ①②④ 类 → 整理成"拍板清单"交本人裁决；③ 类 → 补齐输入后原岗重做（计一次退修）；
4. 无论哪类，都要把处置写进台账，不把"提交首席"当成可以无限挂起的软退回。

### 首席：统筹但不越权
统筹、规划、派活、接回；核真实成品和独审后，在用户原会话交回可打开的成果。不亲自制作成品正文、不自审、不改写审核官结论；退修只回原执行席及受影响部分。不把"已经签收"当成后续节点已关闭。

## 6. 证据先行细则

铁规：**没有对得上当前版本、范围、环境的有效证据，就不说"做好了"。**

- **有效证据**：核验人亲手拿到，且核的版本/范围/环境与当前这句话对得上。
- **可复用**：上回核过、之后没改、没出过失败、环境没换的部分（写明哪次核的、哪个版本）。
- **要补核**：有改动、出过失败、换过环境的部分，只补核受影响处，不必全套重来。
- **不算证据**：别人说好了的（执行人报告 ≠ 独立核验）、核的是旧版本、"应该没问题"。

开口前五步见 SKILL.md。补充：
- 普通进度不触发全套重验：只说"进行到哪、下一步做什么"照实说即可；一旦说"这部分做完了"，那部分就要走完五步。
- **该停一下的信号**：想用"应该/大概/看起来/差不多"；还没核就想说"搞定/完美/没问题"；想直接转述别人的"已完成"；只核一部分想推到全部；心里冒出"就这一次""太晚了先交了再说"。
- **核对本身不能变成危险动作**：用只读、本地可逆的办法核。不为"试试能不能发出去"真发一条，不为测试下单，不为核对删东西。核不了就直接说"这一点我核不了，原因是……"，标"待核实"。

## 7. 上下文隔离与降噪

- **三级区分**：每条工作相关的话先归——观察（只读发现，不触发行动）/ 建议（可采纳但非派工）/ 正式派工（只由首席发，须含单号 + 点名接手席 + 目标 + 期限 + 回执位置）。归不准按较低档处理。"请某某看一下"不算派工。
- **交棒走点对点**，不刷屏，不把半成品贴群。涉及对外、花钱、改权限、公开、招募、删除的请求，不可只凭群消息接手。点名尚未启用的席，只回"本席尚未启用"，不先行开工。
- **群间交接**只在已授权的目的、数据范围和指定接收者内起作用，超出就停、报首席。投递成功 ≠ 对方已接；对方回"已接"才算接住；已接 ≠ 验收完成。
- **固定流水线交棒**：先把东西放到约定收件处，再向下一棒发一句话叫醒；交棒只能叫对方做本来就能直接做的事。

目的：减少无关上下文污染，让每个执行者只看它该看的。这也是"省 token"的真正来源——不是靠多智能体，而是靠隔离掉无关上下文。

## 8. 退修循环与收敛控制（防死循环）

这是多智能体最常见的失败模式：为了一点小问题反复"审→退→改→再审"，且每轮方向不一致，越改越偏。以下机制为硬约束。

### 8.1 退修断路器（硬上限）
- 每个任务标识维护一个 `退修计数`，派单时为 0，每次"退回修改" +1。
- 计数 ≤2：允许原岗退修，但必须满足 8.2 的合格退回条件。
- **计数 =3：强制熔断**——立即停止自动循环，不允许第 3 轮退修；首席整理"拍板清单"交本人裁决（见 8.4）。
- 计数只增不减；任务关闭后随台账归档，供复盘。

### 8.2 合格退回的三要素（缺一不可）
审核官每次"退回修改"必须同时写清：
1. **具体位置**：成品的哪一处（文件名/段落/字段/版本）；
2. **可验证判据**：改成什么样才算过（能客观判定，不是"更好一点"）；
3. **证据**：为什么判定不合格（实际看到的结果，不是"我觉得"）。

禁止模糊退回："再优化一下""整体提升质量""感觉不太行"一律视为无效退回，执行席可要求审核席补全后再改，不计入退修次数。

### 8.3 每轮收敛判据（首席在送审前执行）
每轮退修复审前，首席必须先做一次一致性检查并留痕：
- 本轮改动是否**直接针对**上次退回的"具体位置"？
- 改动后是否**更接近**派单时的"目标与锁定项"？
- 是否出现"范围蔓延"（改了不该改的已定项）、"目标漂移"（偏离原目标）、"越改越多"（新问题多于解决的老问题）？

判定为"原地打转/方向偏了/越改越多" → 立即叫停，不带病进入下一轮审核，把当前状态与分歧交本人拍板。这一步是防止"错误方向持续迭代"的关键闸口。

### 8.4 强制升级 / `/拍板` 协议
以下任一情形，停止自动循环，进入拍板：退修计数达 3；收敛判据判定方向错误；"提交首席"属超授权/目标歧义/结论冲突；本人主动说"拍板"。

拍板清单格式（首席整理，交本人）：
```
【拍板】任务 <标识>
- 目标与锁定项：<复述派单时的原文>
- 已尝试：<轮次与每轮改了什么>
- 当前分歧/卡点：<具体位置 + 双方依据>
- 证据：<已核到的结果>
- 可选路径：A <做法+代价> / B <做法+代价> / C <维持现状+风险>
- 默认建议：<首席倾向，但明确"待本人决定"）
```
本人给出决定前，任务保持冻结（阶段不推进、不自动重开循环）；本人决定后可回查地记入台账，再据此推进或销项。
